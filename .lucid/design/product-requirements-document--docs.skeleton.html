Rolling back a production deployment
Promote a previously built deployment back to production without triggering a rebuild.
Article Body — Prose
Before you begin
You need the Deploy role or higher on acme-platform. Rollback is available on Team and Enterprise plans.

1. Find the target build
Open Home → Recent deployments and locate the build number you want to restore. Only builds with status Ready can be promoted.

2. Promote the build
Select the build, then choose “Promote to production”. The existing artifact is re-pointed at the production alias; no new build minutes are consumed.

3. Verify
Check that the production alias resolves to the promoted build number and that health checks pass within 60 seconds.
Code Sample Block
Tabs: CLI · REST · SDK
$ relay rollback --project acme-platform --to 4816
✓ Promoted build #4816 to production in 11s
✓ Alias acme.io → dpl_4816 · health check passed
Parameters Table
Parameter · Type · Required · Description
project · string · yes · Project slug, e.g. acme-platform
to · integer · yes · Target build number to promote
skipHealthCheck · boolean · no · Bypass the 60s health gate
reason · string · no · Recorded in the audit log
Callout — Note
Note: rollback does not revert environment variables. Change those in Settings → Environment before promoting an older build.
