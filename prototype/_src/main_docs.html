Rolling back a production deployment

Promote a previously built deployment back to production without triggering a rebuild.

Before you begin

You need the Deploy role or higher on acme-platform. Rollback is available on the Team and Enterprise plans — see plan comparison.

1. Find the target build

Open Overview → Recent deployments and locate the build number you want to restore. Only builds with status Ready can be promoted; archived artifacts must be rebuilt first.

2. Promote the build

Select the build, then choose Promote to production. The existing artifact is re-pointed at the production alias, so no new build minutes are consumed.

# promote a prior build, no rebuild
$ relay rollback --project acme-platform --to 4816
✓ Promoted build _H_4816 to production in 11s
✓ Alias acme.io → dpl_4816 · health check passed
$ curl -X POST https://api.relaydeploy.com/v2/rollback \
    -H "Authorization: Bearer $RELAY_TOKEN" \
    -d '{"project":"acme-platform","to":4816}'

200 // dpl_4816 aliased in 11s
import relay from "@relay/sdk";

await relay.rollback({
  project: "acme-platform",
  to: 4816,
  reason: "webhook retry regression",
});
Median 11s across 6 rollbacks this quarter

3. Verify

Check that the production alias resolves to the promoted build number and that health checks pass within 60 seconds. A failed gate reverts the alias automatically.

Parameters

ParameterTypeRequiredDescription
projectstringRequiredProject slug, e.g. acme-platform
tointegerRequiredTarget build number to promote
skipHealthCheckbooleanOptionalBypass the 60s health gate
reasonstringOptionalRecorded in the audit log

Audit log entries

Every rollback writes one deployment.rollback event containing the actor, the source and target build, and the reason string. Entries are retained for 90 days on Team.

Troubleshooting

Rollback does not revert environment variables. Change those in Settings → Environment before promoting an older build, or the restored artifact will read the current values.
